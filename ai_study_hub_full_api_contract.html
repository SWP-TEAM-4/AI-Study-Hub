1. Phân tích nhanh project & kiến trúc API

  • Auth, JWT, User, Admin User

2. Nhận xét ERD quan trọng trước khi code API

Điểm mạnh: ERD đã tách tốt các miền nghiệp vụ: user/master data, learning repository, document/chunk, quiz/test, flashcard, marketplace governance, role/reward/system. Cấu trúc này phù hợp để 3 backend code song song theo owner.

Cần chỉnh nhẹ để khớp task plan/API: community_roles nên thêm granted_by_user_id; documents nên thêm cloud_file_path và có thể thêm updated_at; document_chunks nên thêm token_estimate, source_page, source_section để citation RAG tốt hơn; content_reports/market_reviews cần rule “exactly one target” giữa document/quiz/flashcard.

File HTML này đã dùng response contract theo hướng DTO frontend, không trả trực tiếp entity JPA ra FE.
